面试官问：为什么要用多 Agent？

你答：

我这里用多 Agent 不是为了堆概念，而是因为企业知识库问答本身不是单一步骤的问题。一个用户问题进来之后，系统至少要判断意图、结合上下文改写问题、检索企业知识、基于证据生成答案，还要判断置信度和记录日志。如果全部放在一个 Agent 里，逻辑会变得很耦合，也不方便定位问题。

所以我把它拆成三个核心 Agent：

Intent Agent 负责判断用户意图和连续追问；  
Retrieval Agent 负责调用 RAG 检索链路，拿到 TopK 知识片段；  
Answer Agent 负责基于证据和 Prompt 策略生成答案，证据不足时转人工。

这样做有三个好处：

第一是职责清晰，每个 Agent 只负责一个阶段，后续好维护、好替换。  
第二是流程可控，我用状态机管理 Agent 流转，而不是让模型自由决定所有步骤。  
第三是结果可追踪，如果回答效果不好，我能判断是意图识别错了、检索没召回，还是生成阶段 Prompt 约束不够。

如果面试官继续问：那单 Agent 不行吗？

你可以补一句：

如果只是简单问答，单 Agent 或单条 RAG Chain 就够了。但我这个场景要支持多轮追问、业务意图区分、证据召回、低置信度转人工和日志反馈，所以用多 Agent 会更适合工程落地。这里的多 Agent 也不是一定代表多个大模型，而是把系统能力按职责拆成多个可编排模块。
