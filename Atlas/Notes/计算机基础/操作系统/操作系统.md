举例 1+2 = 3 怎么运行的

![[image-1785156350202.webp|400x112]]
4.继续移 到+ 先传输给控制单元  发现+是运算指令 于是通知运算单元工作 运算单元收到 加 的通知后，就会把状态中的1和2读入并计算，再将计算的结果3存放到状态中
![[image-1785156633299.webp|400x168]]
5. 运算单元返回给控制单元 控制单元将结果传输给读写头 读写头向右继续 把结果3写入到纸带的格子中
![[image-1785156771547.webp|400x118]]

#### 冯诺依曼模型

由上面的基础 定义 计算机基本结构
**运算器  控制器  存储器  输入设备  输出设备**
![[image-1785156980989.webp|400x372]]

其中运算器、控制器是在中央处理器里的
存储器就是常见的内存
输入输出设备则是计算机外接的设备
比如 键盘是输入设备 显示器是输出设备

存储单元和输入输出设备要与中央处理器打交道的话，离不开总线
![[image-1785157220056.webp|400x177]]
接下来，分别介绍内存、中央处理线、总线、输入输出设备
##### 内存
程序 和 数据 都存储在内存 存储的区域是线性的
存储数据的基本单位是 字节
1 字节等于8 bit 
每一个字节都对应一个内存地址
内存地址从0开始 自增排列 最后一个地址为内存总字节数-1

##### 中央处理器
中央处理器 CPU 
32位 CPU 一次可计算 4个字节
64位 CPU 一次可计算 8个字节

32/64通常称为CPU的位宽 代表CPU一次可以计算的数据量

CPU内部还有一些组件，常见的有 **寄存器、控制单元和逻辑运算单元**
控制单元 负责 控制 CPU工作
逻辑运算单元 负责 计算
寄存器 分为 多种类  每种寄存器的功能又不尽相同

**问：为什么有内存还需要寄存器？**
因为内存离CPU太远 而寄存器就在CPU里，还紧挨着控制单元和逻辑运算单元 自然计算时速度会很快

常见的寄存器种类：
**通用寄存器：** 存放需要进行运算的数据
**程序计数器：** 用于存储CPU要执行下一条指令[所在的内存地址]
**指令寄存器：** 用于存放当前正在执行的指令 也就是指令本身 指令被执行完成之前 指令都存储在这里

##### 总线
地址总线，用于指定CPU将要操作的内存地址
数据总线，用于读写内存的数据
控制总线，用于发送和接收信号，比如中断、设备复位等信号，CPU收到信号后自然进行响应，这时也需要控制总线

当CPU要读写内存数据的时候，一般需要通过下面这三个总线：
1. 地址总线 来 指定 内存的地址
2. 控制总线 控制是读或写 命令
3. 数据总线 来 传输数据

##### 输入、输出设备

**输入设备** 
向计算机输入数据 ，计算机经过计算后，把数据输出给
**输出设备**
期间，如果输入设备是键盘，按下按键时是需要和CPU进行交互的，这时就需要用到控制总线了

#### 线路位宽与CPU位宽
数据如何通过线路传输？ 操作电压 低电压表示0 高电压表示1
构造 高低高 信号 其实就是101二进制数据 十进制表示5 
如果只有一条线路 意味着每次只能传递1bit数据 即0或1 那么传输101这个数据 就需要传输3次 效率低
一位一位传输 称为串行 
为提高 传输效率 **线路的位宽**最好一次就能访问到所有的内存地址

CPU想要操作 内存地址 就需要 地址总线
 * 如果地址总线只有1条 每次只能表示 0/1 这两种地址 CPU能操作内存地址最大数量为2 
 * * 如果地址总线只有2条 每次只能表示 00、01、10、11 这四种地址 CPU能操作内存地址最大数量为4 

想要CPU操作4G大的内存，需要32条地址总线，因为2^32 = 4G
如果计算的数额不超过32位数字的情况下，32位和64位CPU之间没什么区别，只有当计算超过32位数字情况下，64位优势才能体现出来

#### 程序执行的基本过程
![[image-1785202484878.webp|400x290]]
1. CPU读取 **程序计数器** 的值，这个值是指令的内存地址，然后CPU的 **控制单元** 操作 **地址总线** 指定需要访问的内存地址，接着通知内存设备准备数据，数据准备好后通过 **数据总线** 将指令数据传给CPU, CPU收到内存传来的数据后 将这个指令数据存入到 指令寄存器
2. **程序计数器** 的值自增，表示指向下一条指令 这个自增的大小，由CPU的位宽决定，比如32位的CPU，指令是4个字节，需要4个内存地址存放，因此 **程序计数器** 的值会自增4
3. CPU分析 **指令寄存器** 中的指令，确定指令的类型和参数，如果是计算类型的指令，就把指令交给 **逻辑运算单元** 运算，如果是存储类型的指令，则交由 **控制单元** 执行

汇编语言 变成 机器码                    CPU真正识别

J: 用在跳转

add 对应MIPS指令操作码 000000 以及最末尾功能码 10000数值固定，查一下MIPS指令集手册就知道
rs 代表 第一个寄存器R0编号 00000
rt 代表 第二个寄存器R1编号 00001

那么用16进制 表示的机器码规则是 0x00011020

编译器在编译程序的时候 **会构造指令** 这个过程叫做指令的**编码**
CPU执行程序的时候 **会解析指令** 这个过程叫做指令的**解码**

CPU使用流水线方式来执行指令
一条指令 四个阶段 四级流水线

1. CPU通过程序计数器读取对应内存地址的指令 **Fetch(取得指令)**
2. CPU对指令进行解码 **Decode(指令译码)**
3. CPU执行指令 **Execution(执行指令)**
4. CPU将计算结果存回寄存器或将寄存器的值存入内存 **Store(数据回写)**
4个阶段 称为 **指令周期**
CPU工作就是一个周期接着一个周期 周而复始

#### 指令的执行速度
CPU的硬件参数都会有GHz这个参数
1GHz 表示时钟频率是1G 代表1秒产生1G次数的脉冲信号 每一次脉冲信号高低电平的转换就是一个周期 称为时钟周期

对于 CPU来说 在一个时钟周期内 CPU仅能完成一个最基本的动作 时钟频率越高 时钟周期越短 工作速度也就越快

一个时钟周期一定能执行完一条指令吗？答案不一定，大多数指令不能在一个时钟周期完成，通常需要若干个时钟周期
不同指令需要的时钟周期不同 加法和乘法都对应着一条CPU指令 但乘法需要的时钟周期要比加法多

## 1.2 磁盘比内存慢几万倍？
![[image-1785219881107.webp|400x211]]
CPU 比喻成 我们的大脑
大脑正在思考的东西 CPU中的 **寄存器**
大脑中的记忆 好比 **CPU Cache**
**CPU Cache** 通常分为 L1、L2、L3三层
L1 距离CPU最近 因此它比L2、L3读写速度都快、存储空间都小
我们大脑的中短期记忆，好比L1 Cache   而长期记忆好比L2/L3 Cache
![[image-1785220268995.webp|400x120]]
对于存储器，他的速度越快、能耗越高、而且材料的成本也是越贵，以至于速度快的存储器的容量都比较小
##### 寄存器
最贵 最靠近CPU的控制单元和逻辑计算单元的存储器 就是寄存器
32位 CPU中 大多数寄存器 可以存储 4 个字节
64位 CPU中 大多数寄存器 可以存储 8 个字节
寄存器访问速度很快，一般要求在半个CPU时钟周期内完成读写
比如2GHz主频的CPU 那么它的时钟周期就是1/2G 也就是0.5ns

##### CPU Cache
SRAM 静态随机存储器
![[image-1785220977450.webp|400x266]]
###### L1高速缓存
访问速度几乎和寄存器一样快 通常只需要2-4个时钟周期 大小在几十KB到几百KB不等

每个CPU核心，都有一块属于自己的L1高速缓存，指令和数据在L1是分开存放的，所以L1高速缓存通常分成指令缓存和数据缓存
###### L2高速缓存
L2高速缓存位置比L1距离CPU核心更远 大小比L1高速缓存更大，在几百KB到几MB不等，CPU型号不同大小也不同，通常大小在几百KB到几MB不等，访问速度则更慢，速度在10-20个时钟周期

###### L3高速缓存
多个CPU核心共用，位置比L2高速缓存距离CPU核心更远，大小也会更大些，大小在几MB到几十MB不等，具体值根据CPU型号而定
访问速度相对慢一点，访问速度在20-60个时钟周期

##### 内存
DRAM 动态随机存取存储器
DRAM存储一个bit数据，只需要一个晶体管和一个电容就能存储，但是因为数据会被存储在电容里，电容会不断漏电，所以需要定时刷新电容，才能保证数据不会被丢失，这就是DRAM被称为动态存储器的原因，只有不断刷新，数据才能被存储起来

DRAM的数据访问电路和刷新电路都比SRAM更复杂，所以访问速度会更慢，内存速度大概在200-300个时钟周期之间

##### SSD/HDD硬盘
也就是固体硬盘 结构和内存类似 相比内存的优点是断电后数据还是存在的，而内存、寄存器、高速缓存断电后数据都会丢失。内存的读写速度比SSD大概快10-1000倍
机械硬盘 通过物理读写来访问数据 速度比内存慢10W左右
由于SSD的价格快接近机械硬盘了，因此机械硬盘已经逐渐被SSD替代

### CPU Cache的数据结构和读取过程是什么样的
CPU Cache是由很多个 Cache Line组成的
Cache Line是CPU从内存读取数据的基本单位
而Cache Line是由各种标志Tag + 数据块 Data Block组成
![[image-1785309328954.webp|400x328]]
L1 Cache一次载入数据的大小是64字节

如何找数据？ **直接映射 Cache**  取余
![[image-1785309494391.webp|386x400]]
对应的CPU Cache Line我们还会存储一个**组标记**
因此 一个内存的访问地址 包括组标记、CPU Cache Line索引、偏移量
![[image-1785309922087.webp|400x274]]
步骤：
1. 根据内存地址索引信息，计算CPU Cache中索引，找出对应的 CPU Cache Line的地址
2. 判断有效位，如果无效直接访问内存，如果有效往下执行
3. 对比组标记和CPU Cache Line中的组标记，确认CPU Cache Line中的数据是我们要访问的内存数据，如果不是的话，CPU就会直接访问内存，并重新加载数据
4. 根据内存地址中偏移量信息，从CPU Cache Line的数据块中，读取对应的字

### 如何写出让CPU跑得更快的代码？
**缓存命中**
因此，分开看 **数据缓存** 和 **指令缓存** 的缓存命中率

如何提升数据缓存命中率？
![[image-1785310708835.webp|288x400]]
![[image-1785310743704.webp|400x96]]
当CPU访问内存数据时，如果数据不在CPU Cache中，则会一次性连续加载64个字节大小的数据到CPU Cache
当访问array[0][0]时，由于该元素不足64字节，于是就会往后顺序读取
array[0][0] - array[0][15] 到CPU Cache中，顺序访问就是利用这一点，所以会比跳跃式访问要快
**如何提升指令缓存的命中率？**
先了解CPU的分支预测器，如果分支预测可以预测到接下来要执行if里的指令，还是else指令的话，就可以提前把这些指令放在指令缓存中，这样CPU可以直接从Cache读取到指令，于是执行速度就会很快

如何提升多核CPU的缓存命中率？
如果一个线程在不同核心来回切换，各个核心的缓存命中率就会受到影响
**把线程绑定在某一个CPU核心上**

### 写回
![[image-1785311833023.webp]]
![[image-1785311977345.webp|312x400]]
### 缓存一致性问题

多核带来的缓存一致性问题
问题：
![[image-1785312185966.webp|359x400]]
要解决 **C和D都能看到相同顺序的数据变化**

两个关键：
* CPU核心对于Cache中数据的操作 需要同步给其他核心
* 要引入锁的概念，如果两个CPU核心里有相同数据的Cache，那么对于这个Cache数据的更新，只有拿到锁，才能进行对应的数据更新

### 总线嗅探
我还是以前面的i变量例子来说明总线嗅探的工作机制，
当A号CPU核心修改了L1Cache中i变量的值，**通过总线把这个事件广播通知给其他所有的核心**，*然后每个CPU核心都会监听总线*
*上的广播事件*，并检查是否有相同的数据在自己的L1Cache里面，如果B号CPU核心的L1Cache中有该数据，那么也需要把该数据更新到自己的L1Cache。
**可以发现，总线嗅探方法很简单，CPU需要每时每刻监听总线上的一切活动，但是不管别的核心的Cache是否缓存相同的数据，都需要发出一个广播事件，这无疑会加重总线的负载。**
另外，总线嗅探只是保证了某个CPU核心的Cache更新数据这个事件能被其他CPU核心知道，但是并不能保证事务串行化。
于是，有一个协议基于总线嗅探机制实现了事务串行化，也用状态机机制降低了总线带宽压力，**这个协议就是MESI协议**，这个协议就做到了**CPU缓存一致性。**
