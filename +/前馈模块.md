# 第一层：什么叫前馈模块（Feed Forward Module）

前馈模块不是一种具体结构，而是一大类模块。

它的共同特点就是：

> **输入 → 若干线性变换 → 非线性变换 → 输出**

也就是说：

```
x

↓

Feature Transformation

↓

y
```

不像 RNN 有循环，

不像 Attention 有 Token 之间的信息交互，

它只负责

> **一个样本（或者一个 Token）自己的特征加工。**

所以：

```
前馈模块（Feed Forward Module）
```

其实是一个**大类别（Category）**。

---

# 第二层：MLP 是最基础的前馈模块

MLP（Multi-Layer Perceptron，多层感知机）

例如：

```
Linear

↓

ReLU

↓

Linear
```

这就是：

```
MLP
```

因此：

> **MLP 是一种前馈模块。**

---

# 第三层：FFN 本质上也是 MLP

Transformer 原论文里面：

```
Linear

↓

ReLU

↓

Linear
```

论文把它叫：

```
Feed Forward Network
```

但是！

你发现没有？

结构是不是和 MLP 一模一样？

答案：

**几乎一样。**

所以很多论文直接写：

```
self.ffn = MLP(...)
```

也有很多论文写：

```
self.mlp = FFN(...)
```

二者经常混用。

---

## 真正的区别在哪里？

其实不是结构。

而是：

**使用场景不同。**

### MLP

强调：

> 这是一个神经网络。

例如：

```
图片

↓

MLP

↓

分类
```

---

### FFN

强调：

> Transformer 里面负责特征变换的那个模块。

例如：

```
Attention

↓

FFN
```

所以：

> **FFN 可以看成 Transformer 中的 MLP。**

很多论文甚至直接写：

> Feed Forward Network (FFN, also called MLP)

---

# 第四层：GLU 是 FFN 的升级

后来大家发现：

普通 FFN：

```
Linear

↓

Activation

↓

Linear
```

表达能力有限。

于是：

Google 提出了：

GLU

结构变成：

```
Linear

↓

分成两路

↓

一路负责特征

一路负责门控

↓

相乘

↓

Linear
```

所以：

GLU

仍然属于：

```
前馈模块
```

只是：

> **带门控（Gate）的 FFN。**

---

# 第五层：SwiGLU

后来又发现：

GLU 用 Sigmoid 不够好。

于是：

把 Sigmoid 换成：

```
SiLU（Swish）
```

于是：

```
GLU

↓

SwiGLU
```

LLaMA、PaLM、Gemma 基本都用它。

所以：

```
SwiGLU
```

其实就是：

> **GLU 的升级版。**

---

# 第六层：MoE

MoE 又更进一步。

以前：

只有：

```
一个 FFN
```

现在：

变成：

```
FFN1

FFN2

FFN3

...

FFN64
```

然后：

Router 决定：

```
Token

↓

Router

↓

选择两个 FFN

↓

输出
```

所以：

MoE 本质是什么？

其实就是：

> **很多 FFN 的集合。**

因此：

MoE 并不是另一种"激活函数"，

而是：

> **FFN 的组织方式发生了变化。**
